# 1.0.0 — Drivers registered on the app() container

**Date:** 2026-10-15

**Changed**

- `src/helpers.php` registers the built-in drivers as `app()` container factory
  bindings instead of calling the commons `implementations()` helper:
  `app()->set('cache.mem', static fn (): string => Memory::class)` (plus
  `cache.memory`, `cache.fs`, `cache.memc`, and `cache.memcached`).
- `Strukt\Cache\Cache` no longer uses the `implementations()` registry or its
  former hard-coded alias map. `resolveDriver()` looks a driver name up on the
  container (`app()->has('cache.'.$name)` / `app('cache.'.$name)`) and otherwise
  treats the value as a driver class; `makeDriver()` builds the driver through
  `app($class, [...])`, passing the filename as the first constructor argument.
- Custom drivers are now registered with
  `app()->set('cache.<name>', static fn (): string => DriverClass::class)`.
- Added default cache bindings on the container: `app(CacheDriverInterface::class)`
  resolves the configured default driver instance, and `app('cache')` resolves a
  default `Cache` facade. The driver defaults to `Memory` and the namespace to
  `default`; both are overridable through `config('cache.default')` (short name
  or driver class) and `config('cache.namespace')`.
- Made the `alias('cache', CacheDriverInterface::class)` registration idempotent
  (guarded by `alias('cache') === null`) so loading the helpers file twice no
  longer throws.

**Why**

- `strukt/commons` removed `implementations()`, and the shared `app()` container
  is a better single home for driver resolution than a parallel registry.
- Binding the interface (and a facade under `'cache'`) lets consumers depend on
  `CacheDriverInterface` instead of a concrete driver.

**Documentation**

- `README.md`: "Configuration and driver registration" now shows container
  bindings, custom-driver registration, the default interface/facade bindings,
  and the `config('cache.default')`/`config('cache.namespace')` overrides.

**Tests**

- `tests/Unit/CacheTest.php`: added "unknown cache drivers are rejected",
  "custom drivers resolve from app() container bindings", "the app container
  resolves a default cache driver and facade", and "the default cache binding
  honors config(cache.default) and config(cache.namespace)". The suite is now
  9 passing.

**Public API impact**

- Behavioural: built-in short names and driver class names resolve as before,
  but custom-driver registration now goes through `app()`. The previous
  `implementations('cache', [...])` registration path no longer exists.
- New: `app(CacheDriverInterface::class)` and `app('cache')` resolve defaults;
  `config('cache.default')` and `config('cache.namespace')` configure them.
- Internal: `Cache::resolveDriver()` no longer carries its own alias map.
